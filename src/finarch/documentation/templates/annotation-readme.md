# Annotation 관리자

평가자가 전달한 JSON을 `annotation/YYYYMMDD/`에 넣고 [관리자 화면](http://127.0.0.1:8893/annotation/)에서 날짜를 선택합니다. 데이터셋 뷰어 상단의 **Annotation 관리자**도 같은 화면을 엽니다. 서버 실행은 [공통 서버 안내](../viewer/README.md)를 따릅니다.

## 읽는 순서

1. 관리자 화면의 **비교 자료 선택·데이터셋 표시 → 유형별 κ → 문제 선택 → 7개 유형의 추가·삭제 내용과 평가자별 판정·주석**
2. 날짜 폴더의 `README.md`: 입력 수, 형식 보완과 오류, 파일 역할
3. `normalized/`: 원본의 Export 구조를 유지한 형식 보완 JSON
4. `_manager/summary.json`과 `normalization-log.jsonl`: 실제 분모, 계산 기준, 원본 해시와 변경 전후

원본 JSON은 날짜 폴더에 그대로 보존합니다. 새 파일을 추가하거나 원본을 변경한 뒤 **새로고침**하면 실제 현재 파일을 다시 읽습니다. **JSON 추가**는 선택한 파일을 현재 날짜 폴더에 저장하며, 같은 이름의 다른 내용은 해시를 붙인 새 파일로 보존합니다. 관리자는 단일 화면을 사용합니다. 수신자에게 전달할 독립 HTML은 **주석 Export**에서 다운로드합니다.

상단 **비교 자료**에서 날짜별 FinanceReasoning·TAT-QA·FinanceReasoning 합본을 전환합니다. 현재 비교의 데이터셋 이름과 평가자 수·문항 수를 표시합니다. 같은 파일을 복사한 중복 비교는 최신 날짜 하나로 표시하며 서로 다른 실행의 판정과 관리자 기록은 합치지 않습니다. 입력에 명시된 실행과 문항·유형 범위가 유일한 현행 배포본과 맞는 legacy 파일은 그 배포본에 연결해 비교합니다. 원본 JSON은 바꾸지 않습니다. 합본의 묶음 이름과 각 문항의 실제 Source type은 구분해 표시합니다.

왼쪽 **전부 성공**은 7개 유형에서 모든 평가자의 저장 판정이 통과이고 형식·본문 오류·미입력이 없는 문항입니다. 성공 판정의 주석만 있는 경우도 포함합니다. **전부 성공외**는 한 유형이라도 실패·유보·오류·미입력이 있는 문항을 표시합니다.

지원 입력은 실제 전달된 `annotator / exported_at / n / labels`와 현행 dataset HTML Export의 `finarch-evaluation-results-v1`입니다. 이름 누락·판정 표기·빈 문자열·명시적 boolean·BOM·코드 블록·문자열 밖의 마지막 쉼표 등 결정 가능한 형식만 보완합니다. 판정·주석의 의미와 추가·삭제 문장을 바꾸지 않습니다. 판정 중복·알 수 없는 유형·평가자 불일치 등은 근거를 보존하고 오류로 표시합니다.

2명은 Cohen κ, 3명 이상은 Fleiss κ를 7개 유형별로 계산합니다. 모든 평가자의 저장 판정이 있고 동일한 본문을 평가한 공통 문항을 사용합니다. 미입력·작성 중·형식 오류·본문 불일치는 제외하며, 유보는 세 번째 판정 범주입니다. 서로 다른 실행·차수·배포본은 별도 묶음입니다. 단일 범주만 있거나 공통 평가가 없으면 `—`로 표시합니다. 문제 필터는 계산 분모를 바꾸지 않습니다. [계산식 출처](https://www.statsmodels.org/stable/_modules/statsmodels/stats/inter_rater.html).

Q/E 문제, A/D 유형, B 다음 유형, R 하단 주석 입력창, V 다음 불일치, N 주석 펼치기, W/S 위아래, X 결과 저장을 사용합니다. 2·3은 주석 없이 저장할 수 있으며 저장 버튼으로 포커스를 보냅니다. 4는 수정할 내용을 적도록 입력창으로 포커스를 보내며 내용이 필수입니다. 1 확인 버튼과 단축키는 제거했습니다. Ctrl/⌘ + Enter로 저장합니다. 입력 중에는 숫자·문자 키가 주석으로 입력되며 문제·유형 이동 단축키는 멈춥니다. 판정 필터는 왼쪽 선택 상자를 사용합니다. **V와 다음 불일치 버튼은 판정·Source type·검색·관리자 필터와 유형 체크를 유지하고 현재 목록 안에서만 이동합니다.** 마지막 불일치에서 첫 불일치로 돌아가며, 현재 목록에 불일치가 없으면 이동하지 않고 버튼을 비활성화합니다.

문제 번호 옆의 **전체 / 성공외 / 7개 유형 체크박스**는 체크한 유형들을 함께 표시합니다. 예를 들어 **전체**를 해제한 뒤 **IC-VALUE 앞·뒤**만 체크하면 두 행만 보입니다. 기본은 모두 체크입니다. **성공외**를 체크하면 성공한 행을 제외하고 실패·유보·오류·미입력 행만 표시합니다. 표시할 행이 없으면 안내를 표시하고 주석 저장을 비활성화합니다. Q/E·새로고침·같은 탭의 페이지 재접속에도 체크 상태를 유지하고 A/D·B는 실제 표시된 유형 안에서 이동합니다. G02와 하단 주석의 저장 대상은 활성 행을 따릅니다. 문항 목록·κ·주석 Export 범위는 그대로입니다.

**본문 맨 아래에 주석 입력창을 바로 표시**합니다. 저장 대상은 입력창 위의 **문제 번호 · 현재 유형**이며 구분 버튼은 **2 재검토 요청 / 3 평가 이유 문의 / 4 문항 수정 필요**입니다. 문의 두 종류는 평가자를 지정하고, 기본 주석은 빈 내용이며 설명 없이 저장할 수 있습니다. 2·3 선택 시 저장 버튼으로 포커스를 보내 Enter로 바로 저장합니다. 4 선택 시 입력창으로 포커스를 보내며 수정할 내용을 필수로 입력합니다. 행 선택·A/D에 따라 저장 대상이 바뀌며 작성 중인 내용은 문항·유형별로 유지합니다. 새로 페이지를 불러오기 전에는 저장해 주세요. 주석 저장 버튼 또는 Ctrl/⌘ + Enter로 저장·수정합니다. 기존 문항 전체 확인·메모도 보존합니다. 입력창 아래의 종류별 체크박스로 목록을 함께 필터합니다. 요청 없음·재검토·이유 문의·문항 수정·관리자 기록을 필터하며 이전 확인 필터는 실제 이전 기록이 있을 때만 표시합니다. 관리자 기록은 `_manager/reviews.json`, 변경 전후는 `review-history.jsonl`에 보존하며 원본 평가·κ를 바꾸지 않습니다. 입력이 바뀌면 이전 확인·요청을 **입력 변경**으로 구별합니다. 이전 확인 완료는 내부 기록으로 보존하고 평가자 문의·수정 HTML에는 넣지 않습니다.

**주석 Export → HTML 저장 / 전체 ZIP 저장**으로 `annotator1_김진수.html`, `annotator2_정유미.html`, `repair_20261001.html`처럼 요청이 있는 수신자 이름·날짜를 담은 HTML을 받습니다. 평가자별 파일에는 본인 요청·주석·원래 평가와 검증된 질문·perturbed 전체 본문을 담고, 수정용 파일에는 문항 수정 요청을 모읍니다. 받은 파일은 서버 연결 없이 검색·종류 필터·Q/E로 읽습니다. 입력이 바뀐 이전 요청은 내보내기에서 제외하며 목록 필터는 내보내기 범위를 바꾸지 않습니다. 읽기용 다운로드이며 상대방에게 자동 전송하지 않습니다.

데스크톱에서는 **100% 글씨와 기본 줄 간격·여백**을 사용하며 일반 본문은 14px입니다. **유형명**은 첫 줄, **상태·주석 표시·G02 ↗**는 둘째 줄입니다. 비교 표의 **평가자 영역은 합계 40%, 유형·본문은 합계 60%**입니다. 40%를 평가자 수에 따라 균등하게 나눕니다. 본문·평가자 주석은 세 줄 미리보기이며 **전체**·**주석 전체**로 펼쳐 원문 전체를 읽습니다. 높이를 강제로 압축하지 않으며 내용이 길면 페이지를 스크롤합니다. PC 전용 배치를 사용하며 모바일 화면 전환은 없습니다.

관리자 입력은 **2·3·4 버튼 → 문의할 평가자(2·3만) → 긴 한 줄 주석 입력창 → 주석 저장** 순서입니다. 입력창은 기본 38px 높이로 필요하면 세로로 늘릴 수 있으며 기존 여러 줄 주석의 줄바꿈은 보존합니다. 자동 저장하지 않고 버튼 또는 Ctrl/⌘ + Enter로 저장합니다. 저장한 주석의 전체 내용·수정·기록 제거·기존 문항 전체 메모는 **저장된 주석**을 펼쳐 확인합니다.

각 유형의 **G02 ↗** 버튼이나 `G` 키로 현재 문제·유형의 원본과 perturbed 전체 본문을 새 탭에서 확인합니다. 관리자 화면의 필터·검색·선택을 유지합니다. 실행·차수가 없는 JSON은 저장 편집과 전체 본문을 유형별로 대조한 기록만 연결하며, 근거가 없거나 본문이 다르면 **G02 ? (미확인)**입니다.

문제 목록의 **Source type**에서 FinQA·TAT-QA·FinanceMath·FinanceReasoning을 선택할 수 있습니다. 판정 필터·검색과 함께 적용하며 조건에 맞는 모든 문항을 한 번에 표시합니다. 앞/다음 목록 버튼 없이 스크롤로 확인하며 Q/E·V는 선택한 출처 안에서 이동합니다. 문제 번호 아래에도 출처를 표시합니다. κ는 비교 묶음 전체 기준입니다. 출처 정보는 저장 원본과 취합 해시를 읽고, 실행 정보가 없는 입력은 저장된 추가·삭제 본문까지 정확히 대조합니다. 근거가 없거나 출처가 서로 다르면 `출처 미확인`입니다. 비교 JSON의 `source_reference`에서 원본 ID·근거 경로를 확인할 수 있습니다.
