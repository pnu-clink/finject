제공된 응답 스키마에 맞는 JSON 객체 하나를 반환하세요. 아래 절은 기존 필드를 설명하며 스키마의 JSON 키 순서를 바꾸지 않습니다. 설명과 근거 필드를 같은 JSON 객체에 넣으세요. 필드를 추가하거나 객체를 Markdown으로 감싸지 마세요.

ANSWER:
- 숫자로 답할 때는 질문과 본문에서 요구한 단위·배율로, 부호가 반영된 JSON 숫자를 사용하세요. 최종 결과를 `answer_format.decimal_places`에 맞춰 반올림하세요. 중간 계산값은 반올림하지 마세요.
- 숫자 `answer`에는 입력값이나 중간 계산값이 아니라 필요한 반올림을 거친, 질문이 요구한 최종 결과를 넣어야 합니다.

ANSWER_META:
- 숫자로 답할 때 `answer`가 0보다 작으면, 그리고 그때에만 `answer_meta.negative`를 true로 하세요. 0이나 양수라면 false입니다.
- `answer_meta.scale`에는 적힌 숫자의 배율을 기록합니다: one, hundred, thousand, million, billion, trillion, percent. 12.5%는 0.125가 아니라 숫자 12.5와 scale percent로 적습니다. scale은 표현을 기록하는 값이며 답에 배율을 다시 곱하라는 지시가 아닙니다.
- `answer`가 null이면 `answer_meta.negative`와 `answer_meta.scale`도 모두 null이어야 합니다.

CLASSIFICATION:
- `classification`은 풀이 지시에서 요구한 분류명을 기록합니다. 분류명을 요구하지 않으면 null을 사용합니다.

EXPLANATION:
- 영어로 간단한 설명을 쓰세요. 숫자로 답한다면 부호·단위·배율을 포함해 질문이 요구한 최종 결과를 설명에 명시하세요. 최종값과 그 의미가 설명과 일치해야 합니다.
- 객체를 반환하기 전에 설명에 적은 최종 숫자를 `answer` 및 메타정보와 대조하세요. 계산을 설명할 때 관련 입력 숫자를 정확하게 옮기세요.
- 설명은 2,000자 이내로 작성하세요.

EVIDENCE:
- 제공된 본문에서 근거가 되는 정확한 발췌문을 `evidence`에 넣으세요. 원문을 정확히 인용하고 뒷받침 문장을 지어내지 마세요.
- 각 근거 항목은 본문에서 이어지는 하나의 구간을 글자 그대로 인용해야 합니다. 대소문자·구두점·공백·줄바꿈·숫자 표기를 보존하세요. 떨어진 구간은 별도의 배열 항목으로 넣으세요. 말줄임표를 삽입하거나 인용문을 정규화하거나 떨어진 조각을 하나의 인용문으로 이어 붙이지 마세요. 설명을 뒷받침하는 데 필요한 만큼만 짧게 인용하세요.
- 빈 evidence 배열은 인용한 구간이 없음을 나타내며, 그것만으로 숫자 답변이 되지는 않습니다.
- 근거 발췌문은 최대 12개, 발췌문 하나는 최대 1,500자로 제한하세요.
