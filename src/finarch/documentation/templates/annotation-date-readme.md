# __DATE__ Annotation 결과

입력 __FILES__개 파일을 읽었습니다. 형식 보완 __REPAIRS__건, 확인할 형식 오류 __ISSUES__건입니다. 이 수치는 파일 형식 처리 결과이며 데이터셋 의미 정답이나 사용자 확인 완료를 뜻하지 않습니다.

## 확인 순서

보조 label의 옛 EA 번호는 안정된 type 경로와 함께 확인한 경우에만 현재 번호로 보완합니다. `06-ea-earlier-input / EA_02`는 `EA_01`, `07-ea-later-input / EA_03`는 `EA_02`입니다. [기존 번호 변경 기준](../../src/finarch/dataset/90-operations/ea-label-migration-readme-template.md)을 따르며 판정·주석·추가/삭제 본문은 그대로 보존합니다. 보완 규칙이 바뀌면 이전 내부 처리 기록도 `_manager/*-previous-*.json`에 보존합니다.

1. [Annotation 관리자](http://127.0.0.1:8893/annotation/?date=__DATE__)에서 날짜와 문제를 선택합니다. 7개 유형의 추가·삭제 문장, 평가자별 판정과 주석, 판정 불일치·실패·유보·미입력을 나란히 확인합니다.
   유형명 아래 상태·주석 표시 옆의 **G02 ↗** 또는 `G` 키로 같은 문제·유형의 저장된 원본·perturbed 전체 본문을 새 탭에서 확인합니다. 평가 JSON과 기록을 대조할 수 없으면 **G02 ? (미확인)**입니다.
2. [_manager/summary.json](_manager/summary.json): 유형별 κ, 일치율, 포함·제외 문항 수, 입력 파일 SHA-256.
   [_manager/comparison.json](_manager/comparison.json)에는 모든 문제의 7개 유형·평가자별 판정과 주석이 함께 저장됩니다.
3. [normalized](normalized): 입력의 Export 구조를 유지한 형식 보완 JSON. 원본 이름 앞의 12자리 해시는 해당 원본을 가리킵니다.
4. [_manager/normalization-log.jsonl](_manager/normalization-log.jsonl): 보완 규칙, 원본 해시, 값의 변경 전후. `_manager/<해시>.json`에는 원본에서 읽은 기록·오류·보완 내역을 보존합니다.

날짜 폴더의 최상위 JSON이 원본 입력입니다. 덮어쓰지 않습니다. 관리자 화면의 **새로고침**으로 새 입력을 반영하며 **입력 파일**에서 원본·보완본·로그를 확인할 수 있습니다. 같은 사람의 여러 파일은 한 평가자로 취급하며, 중복 판정이 서로 다르면 파일을 선택해 해결할 수 있도록 오류로 표시합니다.

목록의 **Source type**을 판정 필터·검색과 함께 사용합니다. 조건에 맞는 모든 문항을 한 번에 표시하며 앞/다음 목록 버튼 없이 스크롤로 확인합니다. Q/E와 V도 선택한 출처 안에서 이동합니다. 출처는 저장 원본과 실제 변경 본문을 대조하며 `_manager/comparison.json`의 문항별 `source_type`·`source_reference`에 종류와 근거를 보존합니다. 근거가 없는 출처는 `출처 미확인`입니다. 목록 필터는 전체 비교 묶음의 κ 분모를 바꾸지 않습니다.

κ는 전원 공통 저장 판정의 실제 문항 수를 분모로 사용합니다. 없는 판정은 통과·실패·유보로 채우지 않습니다. 입력에 없는 실행·차수·배포본 정보는 만들어 넣지 않습니다. `annotator / labels` 입력은 동일한 추가·삭제 본문을 가진 문제·유형끼리 비교합니다.

문제 번호 옆의 **전체 / 7개 유형 체크박스**는 선택 문항의 표를 필터합니다. 기본은 모두 체크이며 **전체**를 해제하고 IC-VALUE 앞·뒤만 체크하면 두 유형의 내용·판정·주석만 보입니다. 체크가 없으면 안내를 표시합니다. Q/E·새로고침·같은 탭의 페이지 재접속에도 체크를 유지하며 A/D·B는 체크한 유형 안에서 이동합니다. G02 연결과 하단 주석의 저장 대상은 활성 행을 따릅니다. 문항 목록·κ 계산 분모·내보낼 요청 범위는 바꾸지 않습니다.

**본문 맨 아래에 관리자 주석 입력창**을 바로 표시합니다. 입력창 위의 **문제 번호 · 현재 유형**에 저장하며 **2 재검토 요청 / 3 평가 이유 문의 / 4 문항 수정 필요** 버튼으로 구분을 고릅니다. 문의 두 종류만 평가자를 지정합니다. R로 입력창에 이동하고 주석 저장 버튼 또는 Ctrl/⌘ + Enter로 저장합니다. 2·3은 빈 주석이 기본이며 저장 버튼으로 포커스를 보내 Enter로 바로 저장합니다. 4는 입력창으로 포커스를 보내며 수정 내용이 필수입니다. 요청은 선택한 한 유형에 기록합니다. 1 확인 버튼과 단축키는 제거했습니다. A/D·문항 이동 시 작성 중인 내용은 해당 문항·유형에 유지합니다. 페이지를 새로 불러오기 전에는 저장해야 합니다. 기존 문항 전체 확인·메모는 보존합니다. 입력창 아래의 종류별 체크박스는 여러 종류를 함께 표시하며 Source type·판정·검색과 결합합니다. 요청 없음·재검토·이유 문의·문항 수정·관리자 기록을 필터하며 이전 확인 필터는 실제 이전 기록이 있을 때만 표시합니다. 저장을 시작하면 `_manager/reviews.json`과 변경 전후를 보존하는 `_manager/review-history.jsonl`이 생깁니다. 원본 판정과 κ는 바뀌지 않습니다. 입력이 바뀐 기록은 **입력 변경**으로 구별합니다. 이전 확인 완료는 내부 기록이며 문의·수정 HTML에는 넣지 않습니다.

**주석 Export**는 현재 비교 묶음 전체의 요청을 `annotator1_평가자이름.html`, `annotator2_평가자이름.html`, `repair___DATE__.html`로 다운로드합니다. 개별 HTML 또는 전체 ZIP을 선택합니다. 요청이 있는 파일만 생성하며 수신자는 별도 viewer 설치 없이 본인 요청·주석·원래 평가·검증된 전체 문장을 읽습니다. 수정용 HTML에는 문항 수정 요청을 한 번씩 모읍니다. 이전 입력 요청은 제외하고 이유를 표시합니다.

데스크톱은 이전 압축 화면보다 125% 큰 글씨, 간결한 집계, 유형명 아래 상태·주석/G02를 두는 두 줄 배치, 본문·주석 두 줄 미리보기를 제공합니다. 비교 표의 평가자 영역은 합계 40%, 유형·본문은 합계 60%이며 평가자 폭은 균등하게 나눕니다. **전체 / 주석 전체**로 원문을 펼칠 수 있으며 길면 표 내부에서 스크롤합니다. 관리자 입력은 **2·3·4 버튼 오른쪽의 34px 한 줄 입력창 → 오른쪽 주석 저장**이며 2·3은 입력창 앞에서 수신 평가자를 고릅니다. 자동 저장하지 않으며 기존 여러 줄 주석도 줄바꿈을 보존합니다. **저장된 주석**을 펼쳐 전체 내용·수정·기록 제거·기존 문항 메모를 확인합니다. PC 전용 배치를 사용하며 모바일 화면 전환은 없습니다.
