# 평가 HTML · 필터 기반 이동 확인

## 변경 사항

- `Q/E`는 판정 필터와 문제 번호 검색에 일치하는 이전/다음 문제로만 이동합니다. 해당 문제의 현재 유형도 일치하면 유지하고, 아니면 일치하는 첫 유형을 엽니다.
- ←/→ 버튼과 키도 같은 필터·검색에 일치하는 이전/다음 항목만 이동합니다.
- `v`는 다음 저장된 유보·실패, `V` 또는 `Shift+V`는 이전 저장된 유보·실패로 이동합니다. 현재 필터·검색과 문제별/유형별 모드를 유지합니다. 미평가·미확인 임시 판정은 유보로 간주하지 않습니다.
- 입력창·대화상자·IME 조합 중에는 이동하지 않습니다. 끝에서는 머물며 처음으로 순환하지 않습니다.
- `A/D`의 같은 문제 내 유형 이동과 자동 판정·저장 규칙은 유지합니다.

`viewer/dataset/evaluation/workspace.js`의 `evaluationFilteredEntries`를 목록·문제 이동·항목 이동·유보/실패 이동이 공유합니다. `assets.py`로 공통 화면을 다시 조립하여 이후 평가 HTML Export에도 반영했습니다.

## 읽는 순서

1. `validation.json`: 수정한 실제 다운로드 HTML 경로, 변경 전후 해시, 배포본 ID·내장 자료 보존 검사와 브라우저 확인 여부.
2. `terminal.log`: 자동 검사·HTML 변경 결과.
3. `workspace-checks.json`: 이동·입력 보호·판정 보존 13개 회귀 검사.
4. `original-html/`: 변경 전 HTML의 독립 백업.

평가 화면은 Downloads의 기존 `20261003-003-평가.html`, `20261003-concat-002-평가 (1).html`, `20261003-concat-002-평가.html`을 새로 열거나 새로고침합니다. 문항 압축 자료·배포본 ID·평가 JSON 형식은 유지하므로 기존 Import와 평가자별 브라우저 임시 기록을 그대로 사용할 수 있습니다. 이미 열려 있는 탭은 옛 코드를 사용하므로 재로딩이 필요합니다.

```shell
node src/finarch/dataset/checks/test_evaluation_workspace.cjs
# 필터·검색 이동, v/V, 입력 보호와 판정·주석 보존을 검사합니다.
```

브라우저 도구의 보안 정책이 `file://` 열기를 거부하여 실제 다운로드 HTML의 브라우저 동작 검사는 수행하지 못했습니다. 우회하지 않았으며 자동 검사 통과를 브라우저 확인 완료로 간주하지 않습니다. LLM 호출과 제작·평가 판정 변경은 없습니다.
